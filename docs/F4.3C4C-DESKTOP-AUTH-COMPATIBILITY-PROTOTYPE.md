## 2. Arquitetura provada (contrato da futura Desktop)

```
login explícito (loginUser)             [backend sintético]
        │  sessão {uid, token HMAC, expiresAt}
        ▼
DesktopAuthBridge.ensureAuthenticated()   ← chamado EXPLICITAMENTE (nunca no boot)
        │ 1. valida sessão local (ausente/expirada => bloqueio)
        │ 2. POST /issueFirebaseAuthToken  (Bearer sessão; body IGNORADO)
        │      401 => SessionExpired · 403 => SessionRevoked (inclui inativo)
        │ 3. signInWithCustomToken(custom token)   [Auth Emulator REAL]
        │      falha => FirebaseAuthFailure + signOut
        │ 4. currentUid == session.uid?  não => UidMismatch + signOut
        ▼
   Authenticated  →  Firestore com request.auth  →  Rules-alvo F4.3C3 decidem
```

- **Estados explícitos (11)**: `Idle`, `Authenticating`, `Authenticated`,
  `SessionMissing`, `SessionExpired`, `SessionRevoked`, `FirebaseTokenFailure`,
  `FirebaseAuthFailure`, `UidMismatch`, `Offline`, `LoggedOut`.
- **API**: `ensureAuthenticated()`, `logout()`, `dispose()`, `currentUid()`,
  `authState()`, `trackListener()/activeListeners()`.
- **Fail-closed em tudo**: qualquer falha => estado de bloqueio; Firestore continua
  NEGADO pelas Rules (sem fallback anônimo, sem fallback de Rules abertas, offline
  não abre nada).
- **Listeners**: todo `onSnapshot` é rastreado; logout/dispose/troca de usuário
  encerra TODOS (nenhum listener sobrevive com credencial antiga).

## 3. Backend sintético (contratos espelhados, zero produção)

`src/synth-backend.mjs` — HTTP em memória (porta efêmera), 3 usuários FICTÍCIOS
(U1/U2/U3 "Sintética/Sintético"), secret de TESTE, TTL reduzido:

| Contrato | Comportamento espelhado |
|---|---|
| `POST /loginUser` | credencial válida => sessão HMAC `{uid, sv, exp}`; senha errada 401; inativo 403 |
