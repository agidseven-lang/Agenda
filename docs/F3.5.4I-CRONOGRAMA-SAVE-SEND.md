# F3.5.4I — Correção crítica do Salvamento/Envio de Cronograma ao cliente (Desktop 1.0.200)

Base: **v1.0.199** SHA `891150fb88e2c7c0d5e5885b4f71ec3e206912c2` (o SHA do mandato tinha um dígito duplicado;
este é o correto — confere com a tag/build). Branch: `desktop/f354i-cronograma-save-send-fix-1.0.200`.

## 1. Causa-raiz (PROVADA por reprodução determinística — não assumida)

**A falha NÃO é de rede e NÃO é regressão da 1.0.199.**

- **Diferencial 1.0.198 × 1.0.199** (`git diff v1.0.198 v1.0.199 -- desktop/src/renderer/index.html`): exatamente **3 hunks**,
  todos confinados ao setor `edicao_cards` — `kbv2SlaLiveData` (leitura de `t.dueAt`, display), `saveCardsBatch`
  (`startAt/dueAt` do card) e `saveCardsEdit` (`startAt/dueAt` + `cardDeadlineRev`). Todos usam `Number(dtMs(...))||0`
  (nunca `undefined`/`NaN`). **`saveTask` — o caminho do "Enviar para o cliente" do Cronograma — é byte-idêntico à
  1.0.198.** A hipótese prioritária (startAt/dueAt) está **descartada com prova**.

- **Mecanismo real:** no wizard, cada slot de tema entra em `state.form.contents[i]` **somente quando o usuário digita**
  (binds `data-ctema`/`data-cleg`, linhas ~8595-8596: `state.form.contents[i]=state.form.contents[i]||{}`). Quando a Social
  preenche temas **fora de ordem ou parcialmente** (ex.: preenche o 1 e o 11; deixa 2-10 em branco), `f.contents` torna-se
  um **array ESPARSO** — `f.contents.length===11` com **buracos = `undefined`** nos índices 1..9.

- **Ponto exato do defeito — linha ~8713:** `if(f.contents.length)data.cronContents=f.contents;` grava o array **cru**
  (com buracos) como `cronContents`. O Firestore **rejeita `undefined` em qualquer ponto da árvore** (inclui buracos de
  array, pois o SDK itera `0..length-1`): `FirebaseError [invalid-argument]: Unsupported field value: undefined (found in
  field cronContents.1)`.

- **Mascaramento — linha ~8742:** o `catch(e)` genérico de `saveTask` transforma **qualquer** erro (inclusive esse
  `invalid-argument` de validação) em `alert('Não foi possível salvar a tarefa. Verifique a conexão e tente novamente.')`
  — sugerindo rede quando o problema é o payload.

- **Variante C (mesmo efeito):** um tema com propriedade `undefined` explícita (`{tema:'x', legenda:undefined}`) gera
  `Unsupported field value: undefined (found in field cronContents.1.legenda)` → mesmo catch genérico.

**Por que os testes não pegaram (item 44):** as suítes existentes constroem `f.contents` **denso**
(`[{tema,legenda},...]`); nunca reproduzem os buracos/temas parciais do preenchimento real fora de ordem.

Reprodução: `desktop/scripts/f354i-repro.mjs` (roda o `saveTask` REAL + mock fiel do Firestore). Cenário **A** (11 temas
contíguos) SALVA; **B** (esparso) → catch genérico mascarando `invalid-argument` real em `cronContents.1`; **C**
(nested undefined) → `cronContents.1.legenda`.

## 3. Correção cirúrgica (plano)

Somente `saveTask` (caminho de save) + helpers novos + estado do botão. **Nada** de Card Premium/Worker/Cloudflare/
cache-bust/mensagem/portal (congelados — só CHAMO o gerador aprovado após o save confirmado).

- **C1 — saneamento recursivo (`cronSanitizeDeep`)**: remove `undefined`, **compacta arrays esparsos** (remove buracos),
  preserva `null`/arrays/`Date`; NaN/Invalid Date são bloqueados na validação (não coeridos em silêncio).
- **C2 — temas compactados**: `cronContents` passa a `f.contents.filter(c=>c&&(c.tema||c.legenda))` (mesmo padrão já usado
  no envio, ~7346) — mantém todos os temas PREENCHIDOS, descarta vazios/buracos.
- **C3 — validação (`cronValidateSend`)**: título/cliente/≥1 tema (setor cliente) + datas parseáveis quando informadas;
  em falha, bloqueia e preserva o wizard (não escreve).
- **C4 — escrita idempotente + read-back**: id estável `f._draftId` (`.doc(id).set(data)`), read-back de campos
  essenciais (taskId/title/sector/cliente/status) antes de liberar o compartilhamento.
- **C5 — erro classificado (`cronClassifyError`)**: permission-denied / unavailable|deadline-exceeded (rede) /
  unauthenticated / invalid-argument (validação) / aborted / inesperado (código `CRON-XXXX`). "Verifique a conexão"
  **só** com code de rede/offline.
- **C6 — observabilidade (`cronDiag`)** via `desktopAPI.diagLog` (canal aprovado): cron.send.start/payload.validated/
  firestore.write.{start,success,failure}/readback.{start,success}/token.ensure.*/message.build.*/whatsapp.open.*/
  send.complete. Em falha: stage/errorCode/errorName/msg sanitizada/taskId(sha curta)/uid(mascarado)/ts/versão/online/tentativa.
  Sem conteúdo de temas/dados sensíveis.
- **C7 — estado "Salvando cronograma…"**: botão desabilitado durante a operação (feedback), reabilitado em sucesso/falha.
