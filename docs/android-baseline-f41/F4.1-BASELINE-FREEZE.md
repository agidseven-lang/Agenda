## 5. Lacunas funcionais e riscos

- `SlaContract.kt` é **inerte** (flags OFF): contrato SLA presente mas sem engine,
  listener, UI ou notificação. Nenhuma funcionalidade SLA ativa no app.
- Fluxo de reset de senha depende de URLs de Cloud Functions injetadas no CI; em
  build sem essas properties (`resolve_urls=false`, como aqui), o `AuthRepo` retorna
  mensagem amigável em vez de chamar URL — o APC de QA **não** exercita o reset real.
- Inspeção do conteúdo interno do APK (endpoints/WebView/secrets/auth) foi feita no
  **código-fonte do commit exato** (o APK é produto determinístico dessa fonte),
  pois o binário não pôde ser descompactado (egress bloqueado). Assinatura, badging,
  permissões, tamanho e SHA vêm do **APK real** (aapt/apksigner rodaram no CI).
- 8/10 telas equivalentes sem diff pixel (ver §4.4).
