alterar identidade, assinatura, backend, Rules ou Desktop. Fase de implementação
controlada que segue a auditoria read-only **F4.3C** (que marcou o modelo de

## 1. Correções implementadas

### MED-1 — Revogação do token FCM no LOGOUT
**Problema (F4.3C):** ao sair, o app apagava a sessão local mas **não avisava o servidor**
para remover o token FCM do usuário; o dispositivo continuava recebendo push do backend
até o token expirar/rotacionar.

**Correção:** `SessionManager.logout()` agora, **antes** da limpeza local, tenta
`ServerAuthRepository.removeMyFcmToken(sessionToken, fcmToken, deviceId, "android")`
(endpoint oficial, **Bearer da sessão**; o uid é derivado no servidor — o cliente nunca
envia uid). Regras:
- **Timeout CURTO** (`LOGOUT_FCM_TIMEOUT_MS = 3000ms`, `withTimeoutOrNull`): a revogação
  **NUNCA trava** a saída do usuário.
- **Limpeza integral SEMPRE**: mesmo em falha controlada de revogação, o logout segue com
  `firebaseGate.signOut()` + `store.clear(deleteKey=true)` + `fcmRevoker.clearLocal()` +
  estado `LoggedOut`.
- Resultado **sanitizado** `LogoutFcmResult` (categoria apenas, sem token/uid/Bearer):
  `Success | NetworkFailure | Unauthorized | ServerFailure | InvalidLocalState`.

**Arquivos:** `data/session/SessionManager.kt` (logout + `revokeFcmBeforeLogout` + enum),
`data/session/FcmRevoker.kt` (**novo** — `FcmRevoker`/`RealFcmRevoker`, lê SharedPreferences
`fcm`/`token` + `Fcm.stableDeviceId`), `data/auth/ServerAuthRepository.kt`
(`removeMyFcmToken`), `data/auth/AuthApi.kt` + `AuthApiClient.kt` (`postRemoveFcm`),
`data/auth/AuthContract.kt` (`FcmRemoveOutcome`), `core/AppRoot.kt` (loga só a categoria).

### HIGH-2 — Cadastro direto em `/users` DESABILITADO (fail-closed)
**Problema (F4.3C):** `AuthRepo.register` escrevia **direto** em `users/{...}` via SDK
Firestore. Sob as Rules abertas (`/users create: size()<60`), um cliente modificado poderia
**forjar `admin:true`/`role`/`status`** — escalonamento de privilégio.

**Correção:** `AuthRepo.register(...)` **não escreve nada** no Firestore, não cria usuário,
não simula sucesso e não confia em nenhum campo do cliente. Retorna o estado neutro
`Result.RegistrationUnavailable`. A dependência `FirebaseFirestore` foi removida do arquivo.
A UI (`LoginViewModel`) mostra mensagem **neutra e orientadora**:
> "O cadastro de novos usuários é realizado pelo administrador do sistema."

**Arquivos:** `data/AuthRepo.kt` (register → `RegistrationUnavailable`; imports Firestore
removidos), `features/auth/LoginViewModel.kt` (novo ramo `RegistrationUnavailable`).

### MED-2 + Correção 3 — Gate Firebase obrigatório no acesso fora do fluxo normal
**Problema (F4.3C):** `ReminderAlarmActivity` (full-screen intent do lembrete) lia
`users/{respId}` **direto** via `FirebaseFirestore.getInstance()` **sem garantir** que a
identidade Firebase estava estabelecida — potencial `request.auth == null`.

**Correção:** a resolução de foto/nome do responsável só ocorre **dentro** do
`AuthenticatedFirestoreExecutor` (FAIL-CLOSED). Sem sessão/gate, **não consulta o Firestore**;
mantém o payload do próprio intent (fallback seguro, sem PII além do que a notificação já
trouxe). Nunca há fallback não-autenticado.

**Arquivos:** `core/ReminderAlarmActivity.kt` (bloco gated + helper `getUserDocGated`).

### Correção 4 — Executor centralizado de Firestore autenticado
`AuthenticatedFirestoreExecutor` (**novo**) centraliza a regra "só acessa Firestore **após**
`FirebaseSessionGate.ensure()==Ok` **E** `uid do SDK == uid da sessão`". Estados exatos:
`Authenticated | SessionMissing | SessionExpired | FirebaseAuthFailure | UidMismatch |
NetworkFailure`. `withAuthenticatedFirestore { db, uid -> ... }` só executa o bloco quando
`Authenticated`; caso contrário devolve `Denied(estado)` e **não toca** o Firestore.
Defesa em profundidade: revalida o uid do SDK mesmo quando o gate retorna `Ok`.

> Escopo desta fase: aplicado ao acesso **comprovadamente fora do gate**
> (`ReminderAlarmActivity`). Os repositórios já gated (Event/Task/Chat/Users) rodam dentro
> do `MainScaffold` (depois do gate) e **não foram reescritos** — evita risco de regressão.

**Arquivos:** `data/session/AuthenticatedFirestoreExecutor.kt` (**novo**).

### Correção 5 — Logs seguros (sanitização)
**Problema (F4.3C):** o fluxo de reset logava `body.take(200)` (corpo bruto da resposta —
podia conter e-mail/telefone/código/token).

**Correção:** removido qualquer `body.take(...)`. Os logs de `requestPasswordReset`/
`confirmPasswordReset` agora emitem **somente** `endpoint=<lógico>` + `kind=<categoria de erro
de transporte>` + `httpStatus=<int>`. Nunca URL completa, corpo, exceção crua ou PII.
Os valores que chegam ao `Log` no logout (`LogoutFcmResult`) e no lembrete
(`AuthenticatedFirestoreExecutor.GateState`) são **categorias fechadas** — sem token/uid/Bearer
por construção.

**Arquivos:** `data/AuthRepo.kt` (logs de reset), `core/AppRoot.kt` (loga só a categoria).

### Correção 6 — Limpeza de sessão no logout
O logout faz limpeza **integral e idempotente** (igual no sucesso e na falha de revogação):
`Firebase signOut` + cofre (`SecureSessionStore`) + **chave do Android Keystore**
(`deleteKey=true`) + **cache local do FCM** (`fcmRevoker.clearLocal()`) + estado único →
`LoggedOut` (zera navegação/backstack, fonte da verdade do `AppRoot`).

**Arquivos:** `data/session/SessionManager.kt`, `data/session/FcmRevoker.kt`.

## 4. Testes unitários obrigatórios (35) — EXECUTADOS no CI

Arquivo `F43C1LocalHardeningTest.kt`. Rodados via `testDebugUnitTest --tests
"br.com.idseven.agenda.auth.*"` (junto dos testes F4.2B/F4.2C, que permanecem verdes).

**LOGOUT E FCM (1–10)**
1. logout revoga o FCM **antes** da limpeza (prova de ordem: `Success` ⟹ sessão viva no momento da chamada)
2. envia o token FCM e o deviceId corretos (cache local)
3. **não** envia uid do cliente — identidade = Bearer da sessão; `platform="android"`
4. sucesso → `Success` e remove a sessão integralmente
5. falha de rede → `NetworkFailure`, mas **ainda encerra** o logout
6. 401 → `Unauthorized`, mas **ainda encerra** o logout
7. **timeout curto** → `NetworkFailure`, não trava, encerra o logout (`removeFcmCalls==1`)
8. resposta inesperada 4xx (≠401) → `ServerFailure`, mas **ainda encerra** o logout (contrato: 5xx/transporte→`NetworkFailure`; 4xx/malformado→`ServerFailure`, espelha `registerFcmToken`)
9. sem cache FCM → `InvalidLocalState`, **não chama** o endpoint, e ainda encerra
10. logout **sempre** faz `signOut` + `clearLocal` (mesmo com revogação falha)

**REGISTRO (11–16)**
11. register **não escreve** em `/users` → `RegistrationUnavailable`
12. register **nunca** retorna `Ok`
13. register ignora `role`/`admin` forjados (desfecho idêntico)
14. register não é erro de rede (`Err`) — estado neutro
15. register robusto a entradas vazias (sem crash)
16. desfecho singleton sem dados (mesma instância; sem PII)

**SESSION GATE (17–25)** — estados negados retornam **antes** de qualquer `getInstance()`
17. sem sessão → `SessionMissing`, bloco Firestore **não executa**
18. sessão expirada → `SessionExpired`, bloco não executa
19. válida + SDK com uid → `Authenticated` sem re-cunhar (`firebaseCalls==0`)
20. válida + SDK nulo → re-cunha e `Authenticated` (`firebaseCalls==1`)
21. uid divergente (Firebase) → `UidMismatch`, bloco não executa
22. **defesa em profundidade**: gate `Ok` mas uid do SDK diverge na revalidação → `UidMismatch`
23. rede fora no issue → `NetworkFailure`, `Denied`
24. Firebase rejeita custom token → `FirebaseAuthFailure`, `Denied` (bloco não executa)
25. inativo (403) no issue → `SessionExpired` fail-closed

**LOGS (26–30)** — prova de sanitização ao nível de tipo
26. `LogoutFcmResult` (logado em AppRoot) — cada valor rende só o nome, sem segredo
27. `GateState` (logado em ReminderAlarmActivity) — sem uid/token; `NetworkFailure` só o enum
28. segredo no transporte, categoria no log (`lastRemoveSessionToken=="tok"` × `Success`)
29. `RegistrationUnavailable` sem dados dinâmicos
30. conjunto de categorias sanitizadas fechado e estável (exatamente 5)

**SESSÃO (31–35)**
31. logout limpa o cofre com `deleteKey=true` (chave do Keystore), 1×
32. logout apaga o cache local do FCM (`clearLocal`), 1×
33. logout leva o estado a `LoggedOut` (backstack/telas zeradas)
34. logout faz Firebase `signOut`
35. **idempotência**: limpeza integral acontece igual mesmo com revogação 5xx

## 5. Testes instrumentados (13) — DESIGN + QA FÍSICA (NÃO EXECUTADOS neste ambiente)

> cenários estão **desenhados e prontos**, mas **NÃO foram executados**. Não os declaro
> "passando". Requerem emulador/dispositivo com contas sintéticas. Fixtures sintéticas

1. `RealFcmRevoker.read()` devolve `(token, deviceId)` gravados pelo `Fcm.register` (SharedPreferences `fcm`).
2. `RealFcmRevoker.read()` devolve `null` quando o prefs `fcm` está vazio.
3. `RealFcmRevoker.clearLocal()` apaga o prefs `fcm` (read subsequente = `null`).
4. Logout de ponta a ponta remove o token no backend de teste (conta sintética) — verificação server-side em ambiente de teste.
5. Logout com rede desligada encerra a sessão localmente e limpa Keystore.
6. `SecureSessionStore` round-trip real no Keystore (uid/token) + `clear(deleteKey=true)` torna a chave inutilizável.
7. `ReminderAlarmActivity` **sem** sessão: não consulta Firestore; usa foto/nome do intent.
8. `ReminderAlarmActivity` **com** sessão válida (uid casa): resolve foto/nome atuais via Firestore gated.
9. `ReminderAlarmActivity` com sessão expirada: fallback ao intent, sem Firestore.
10. Full-screen intent aparece sobre o lockscreen e liga a tela (comportamento preservado).
11. Cadastro na UI mostra a mensagem neutra e **não** cria doc em `/users` (verificação server-side de teste).
12. Login → gate → listeners Firestore continuam funcionando (regressão F4.2B/F4.2C).
13. Troca de usuário (logout U1 → login U2): sem vazamento de cache/token do U1.

## 8. Runbook de QA física (dispositivo real — owner)

1. Instalar o APK oficial existente (1.0.0 / 129) numa conta sintética.
2. Login → confirmar telas internas (gate OK).
3. **Logout** → confirmar (backend de teste) que o token FCM do device foi removido;
   confirmar que push subsequente ao mesmo device **não** chega.
4. Logout **offline** (rede desligada) → app volta ao login mesmo assim.
5. Abrir tela de **Cadastro** → confirmar a mensagem neutra; confirmar (backend de teste) que
   **nenhum** doc foi criado em `/users`.

7. Repetir o lembrete **logado** → foto/nome atualizados via Firestore gated.
8. Trocar de usuário (logout U1 → login U2) → sem cache/token do U1.
