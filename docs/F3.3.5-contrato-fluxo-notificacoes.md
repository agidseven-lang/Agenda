## 1. Matriz do fluxo Social Media / Cliente / Designer / Admin

Fonte canônica: `deriveCanonicalTaskState(t)` (renderer). 8 fases (`TASK_PHASE`).

| Fase canônica | Gatilho (campos lidos) | Owner | Setor que age |
|---|---|---|---|
| `planning` | cronograma sem designer | social | Social cria/levanta temas |
| `awaiting_designer` | `hasDesigner` & `designerCol`∉{andamento,revisao,concluido} | designer | Designer vai iniciar |
| `designer_producing` | `designerFlowStatus='andamento'` | designer | Designer produz |
| `designer_revising` | `designerFlowStatus='revisao'` | designer | Designer ajusta |
| `designer_delivered` | `designerCol='concluido'` ou `designerFlowStatus='entregue'` | social | Social reenvia ao cliente |
| `awaiting_client_approval` | `cronStatus∈{ready_for_final_client_review,reenviado_cliente}` ou `clientApprovalPhase='final'` | client | Cliente aprova final |
| `client_requested_changes` | `clientReview.status='revisao'` ou `clientFlowStatus='revisao'` | social | Social corrige/reenvia |
| `completed` | `isTaskCompleted(t)` (ver §4) | social | — (encerrado) |

**Por setor (comportamento aprovado):**
- **Social Media:** cria cronograma → levanta temas → envia ao cliente (`persistClientSend`) → recebe aprovação/ajuste → reenvia → envia ao designer (`sendToDesigner`, cria `designerAssignment`+`designerSla`) → acompanha → recebe notificação de **fluxo**.
- **Cliente:** `openClientView`/`renderClientView` — vê só temas/conteúdo/aprovação; `clientReviewAction` aprova/pede ajuste. **Não vê** fluxo interno/SLA; **não recebe** notificação interna.
- **Designer:** recebe após atribuição → inicia/produz/revisa/entrega (`moveStatus`) → recebe **SLA pessoal** (laranja/vermelho/crítico) → bloqueio em atraso crítico.
- **Admin:** supervisiona (`canSeeAll`); vê tudo; **não** é bloqueado e **não** recebe SLA pessoal.

## 4. Contrato de conclusão (F3.3.4 item A)

Fonte **única** read-side `isTaskCompleted(t)` — aprovação FINAL do cliente é a única conclusão:

```
isTaskCompleted(t) = finalApprovalCompleted===true || clientApprovedFlag===true
                   || operationalStatus==='concluido' || cronStatus==='aprovado_final'
                   || clientFlowStatus==='concluido'
```

- `flowCompletedSignal`, `clientCol`, `socialCol` **roteiam** por `isTaskCompleted` (equivalência byte-a-byte provada: 32/32 combinações em `f334b`).
- `isFullyComplete` **NÃO** é roteado — tem guardas duras (designer/pendências/clientReview) + subconjunto de 3 campos (não equivalente). Preservado intencionalmente.

## 5. Contrato de SLA (read-side, sem escrita)

Fonte única: `resolveTaskDisplayState(t,now)` ← `slaPanelFinishMs`/`resolveCanonicalDeadline`
(ordem do prazo: `plannedFinishAt → planDueAt → designerAssignment.endDate → dueDate`).

- **SLA pessoal nasce só após atribuição ao designer** (`designerSla` semeado em `sendToDesigner`).
- Tarefa **sem designer** não entra no painel pessoal.
- **Laranja** exatamente em `prazo − 30min` (`SLA_PANEL_WARN_MS=30min`); contador `slaCount` (ceil): "Vence em 30:00" → "29:59".
- **Vermelho** no prazo (`now ≥ finishMs`); tolerância `SLA_PANEL_GRACE_MS=10min`.
- **Crítico** após a tolerância (`now ≥ finishMs+10min`) → bloqueio operacional (só designer).
- Disparo pontual via boundary timer (`slaMonScheduleBoundary` → `slaibRefresh()` + `notifScanSla()`).
- Monitor **calmo** antes dos 30min = chip verde **"Tudo em dia"** (sem contagem "em X min").

## 6. Contrato de notificações (Local/Electron)

- **Destinatário (roteador puro `resolveNotificationTargets`):**
  - **SLA pessoal** (`sla_*`/`operational_block`) → **somente o designer responsável**. Social/Admin/Cliente **não**.
  - **Fluxo/status** (`flow_*`) → **equipe** (designer + autor + atribuído + supervisão que vê tudo).
  - **Cliente** → nenhuma notificação interna.
- **Canal (hub no main, `windowActive`):** app **visível** (`isVisible() && !isMinimized()`, **sem exigir foco**) → **toast premium in-app**; minimizado/bandeja/oculto → **nativa do SO** (fallback). Nunca os dois (either/or).
- **Card premium:** largura 420px, avatar/**foto real** (`resolveUserIdentity`: diretório → denormalizado → iniciais; nunca letra havendo foto), **sem reticências** em campos essenciais, autor + responsável (mini-foto), severidade por cor, som.
- **Zero provider/write:** sem FCM/Web Push/WhatsApp/Firestore-write (`providerCalled=false`; firebase só `onSnapshot`).
