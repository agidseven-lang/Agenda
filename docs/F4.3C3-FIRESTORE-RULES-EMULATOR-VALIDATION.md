## 3. Rules-alvo (Artefato B) — princípios
`security/firestore/f43c3/firestore.f43c3-target.rules` (PROPOSTA; NÃO É deploy):
- **deny-by-default** (catch-all `match /{document=**} { allow read, write: if false; }`).
- **`request.auth` obrigatório** em tudo; **uid vem SÓ de `request.auth.uid`** (sem confiar em uid do doc).
- **`isActiveUser()`** = `get()` no doc `users` do próprio caller: bloqueia inativo/pendente/removido/excluido/disabled mesmo com token válido — **ponte de revogação na camada de Rules** (a revogação fina por sessionVersion é server-side F4.3C2; Rules não veem claims de token).
- **users**: server-only (deny total ao cliente) — sem ler pass/salt/fcmTokens/PII, sem alterar role/admin/status/sessionVersion, sem criar admin, sem registrar FCM direto.
- **usersPublic**: projeção segura {id,name,role,admin,status,photo,color} — leitura por ativo; escrita só via trigger.
- **events/tasks**: quadro/agenda de EQUIPE (single-tenant) — leitura por membro ativo; ESCRITA endurecida (criador `by`/createdAt/src[/cardsBatchId] imutáveis; `status`/`designerFlowStatus` restritos aos 4 valores canônicos; sem spoof de criador; exclusão só por criador/responsável).
- **chats/messages**: escopo por `participants`; `participants` imutável no update; `by`(sender)==uid; mensagens imutáveis.
- **notifLog/notifPrefs/passwordReset\*/waPreviewDiagnostics**: server-only.
- **Sem tenantId** (sistema single-tenant — não inventado). **Sem exceção anônima. Sem regra baseada só em filtro de UI.**

## 8. Limitações / riscos restantes
- **Ruleset ativo em produção NÃO COMPROVADO** (§2). Uma captura byte-exata nova é pré-requisito antes de qualquer deploy futuro.
- **Modelo de EQUIPE**: events/tasks são lidos por qualquer membro ATIVO (contrato real single-tenant). Escopo por-usuário quebraria o quadro/agenda compartilhados (função da Desktop) → não adotado; documentado como possível endurecimento futuro (item "proposto").
- **Enforcement de EDGE de status** (transições exatas) fica na app; as Rules validam o valor canônico dos 4 estados.
- **`isActiveUser()` custa 1 `get()`/op** (defesa-em-profundidade). Aceitável; documentado.
- **`sessionVersion`** não existe no canônico; revogação fina é server-side (F4.3C2). Rules bloqueiam por status/disabled.
- **Migração**: Desktop precisa de Firebase Auth; Android precisa migrar roster `users`→`usersPublic`. Ambos fora desta fase.

## 9. Recomendação para F4.3C4
Estratégia de migração SEM alterar a Desktop Golden Master até uma fase de release própria:
(a) capturar byte-exato o ruleset ativo atual; (b) migrar Android roster → usersPublic; (c) preparar
Desktop com Firebase Auth em canário isolado; (d) só então promover as Rules-alvo em janela gated,
com rollback ao ruleset vivo. **Cada passo exige autorização própria e deploy manual gated.**
