## 2. Arquitetura nova (evento persistido primeiro; entrega no MAIN)

O escritor de TODA ação real JÁ PERSISTE o evento no documento canônico (`history[]` com `{kind:'moved'|'designer_moved',from,to,at,byId}` — `index.html:6120/6133/6165`; `designerAssignment{designerId,assignedAt,assignedBy,…}`). A F3.5.3 passa a DERIVAR o evento canônico desse registro durável (level-based, como o SLA):

```
ação real → doc atualizado (history[]/designerAssignment — inalterado)
  → notifEvents.deriveTaskEvents(doc)  [evento canônico determinístico]
  → notifierA (MAIN, vivo na bandeja/X): 1º snapshot = BACKLOG completo (estado inicial
    do Firestore) + snapshots seguintes = tempo real — MESMO stream ⇒ SEM lacuna
  → deliverNotification (HUB aprovado: toast premium/bg-window/nativa + clique detail/<id>)
  → entrega aceita ⇒ recibo (userId+deviceId+eventId) + cursor avança (contíguo)
```

- **Evento canônico** (`src/main/notifEvents.js`): `{eventId determinístico (type:taskId:from>to:at:byId — nunca Date.now isolado), type task_assigned|task_moved|task_completed|task_reopened, recipientMode:'all_active_users', taskId, taskTitle, sector, actorId/Name, assignedDesignerId/Name, fromStatus, toStatus, at}`; retenção 30 dias.
- **Categoria A → TODOS os usuários ativos** (ator e atribuído INCLUÍDOS): cada Desktop logada entrega ao seu usuário; inativo/revogado não possui sessão (login/backend bloqueiam) ⇒ não recebe. Filtros antigos u1/u1b/u3 (pessoal/team_flow/seed) REMOVIDOS de `notifier.ts` (fica só `event_new` da Agenda, intacto). Conteúdo oficial verbatim: "Tarefa atribuída/movimentada/concluída/reaberta" + "{ATOR} atribuiu ‘{TAREFA}’ para {DESIGNER}." / "moveu … de {ORIGEM} para {DESTINO}." / "concluiu …" / "reabriu … em {DESTINO}." (nomes reais via diretório `usersPublic`, leitura já permitida pelas Rules vivas; fallback denormalizado; acentos/emojis preservados).
- **Cursor/recibos/deviceId** (`src/main/notifStore.ts`, `userData/idseven-notif-cursor.json`): deviceId único por instalação; cursor POR USUÁRIO só avança após entrega aceita; recibos capados (5000) impedem duplicação em restart/reconexão/replay/janela recriada; logout mantém o histórico do usuário; usuários no mesmo PC isolados. Janela de tolerância de 48h atrás do cursor para docs que sincronizam atrasados (recibos impedem duplo).
- **Recuperação pós-desligamento**: login → notifierA → 1º snapshot re-deriva TUDO → filtra recibos/cursor/retenção → entrega do mais antigo ao mais novo → recibo+cursor por item; falha PARA a fila (não avança cursor) e re-tenta no próximo snapshot/re-eval ≤60s (backoff de transporte já existente no listener F3.4.7 5s→60s).
- **ACK do toast** (`src/main/toastAck.ts` + HUB): roteamento/dedup 1.0.191 preservados byte-a-byte (markSeen no envio; regiões pinadas dos harnesses f343 intactas via guarda `typeof`); ADITIVO: sem `notif-toast-ack` do renderer em 4s ⇒ fallback bg-window/nativa — app "aberto" com renderer falho não perde mais em silêncio.
- **T-30/T-10 (Categoria B) INTOCADAS**: `slaRules.js`, `cardsRules.js`, `slaScheduler.ts`, `bgNotify.ts`, `tray.ts`, `updaterService.ts`, `firebase.ts`, `reminder.ts` — 0 bytes alterados (git diff). `sla_personal` continua SOMENTE o Designer responsável.

## 3. Colagem na Legenda (Setores → Edição de Cards → Nova tarefa)

Pipeline explícito escopado ao formulário (`index.html`, `f353WirePasteRecovery` ligado no `afterForm`): (1) evento `paste` → texto puro no cursor; (2) Ctrl+V/Meta+V/Shift+Insert → clipboard do Electron via IPC `clipboard-read-text` (determinístico, independe do accelerator nativo); (3) menu de contexto próprio Colar/Copiar/Recortar. Guardas: só com `state.form` aberto e só em campos de texto (textarea/input text) — atalhos globais e o clipboard do Card Premium (`_copy`/`copy-card-image`) intocados. Texto SEMPRE simples (HTML vira literal); CRLF→\n; quebras/acentos/emojis preservados; dispara `input` (bind captura → salvo → card → Detalhes).

## 6. Limitações documentadas

`history[].at` é o relógio do cliente que gravou (contrato atual dos escritores 1.0.191 — não alterado nesta fase); ordenação/identidade usam esse carimbo do próprio doc. Recuperação limitada à retenção (30d) e à janela de tolerância (48h atrás do cursor). Toast renderizado com ACK perdido (falha de IPC) pode gerar um fallback visual duplicado — preferível à perda silenciosa (mesma propriedade do ACK da bg-window F3.4.7). Reatribuição offline recupera a atribuição VIGENTE (designerAssignment é estado-nível); intermediárias perdidas não são reconstruíveis do doc.
