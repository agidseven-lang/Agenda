(3) PRÁTICAS DE SEGURANÇA COMPROVÁVEIS NO CÓDIGO
════════════════════════════════════════════

HTTPS/TLS em trânsito
- Cleartext proibido em todo o app: android:usesCleartextTraffic="false" + networkSecurityConfig com base-config cleartextTrafficPermitted="false" (AndroidManifest.xml:20-21; network_security_config.xml:7-9).
- Fail-closed no cliente de auth: URL não-https é rejeitada ANTES de conectar (AuthApiClient.kt:66-68, retorna Transport.BAD_URL).
- Timeouts explícitos: connect 15s / read 20s (AuthApiClient.kt:73-74; também AuthRepo.kt:62-63).
- Firestore/Auth/FCM (SDKs Google) trafegam sobre TLS por padrão (gRPC/HTTPS gerido pelo SDK).
- Observação de rigor: AuthRepo.postJson (reset de senha) NÃO tem o guard startsWith("https://") do AuthApiClient, mas qualquer cleartext é bloqueado no nível da plataforma pelo usesCleartextTraffic=false + network-security-config; as URLs de reset são URIs Cloud Functions Gen2 (https) injetadas pelo CI.

Criptografia em repouso da sessão (Android Keystore + SessionCipher)
- Envelope AES-256-GCM com chave gerada NO Android Keystore, não-exportável: KeystoreSessionCipher (SessionCipher.kt:39-104). setKeySize(256), BLOCK_MODE_GCM, ENCRYPTION_PADDING_NONE, setRandomizedEncryptionRequired(true), tag de 128 bits, IV aleatório de 12 bytes por operação (SessionCipher.kt:57-79).
- Sessão (uid/token/sessionId/expiração/perfil) gravada SOMENTE cifrada em arquivo privado do app em filesDir, com escrita atômica (.tmp + rename) (SecureSessionStore.kt:19-38).
- Device-bound: sessão restaurada em outro aparelho ou após reinstalação não decifra (chave do Keystore ausente) → tratada como inválida (SessionCipher.kt:82-96; SecureSessionStore.kt:10-12,30-38). Reforçado por android:allowBackup="false" (AndroidManifest.xml:15) — o blob não sai por backup.
- Token NUNCA em SharedPreferences puro, DataStore puro, log, Intent, deep link, notificação ou clipboard (invariante documentada e verificável: AuthContract.kt:8-12; SecureSessionStore.kt:11-12).
- Custom Token Firebase é efêmero, confinado ao FirebaseBridge, só em memória, nunca persistido/logado (FirebaseBridge.kt:16-19; FirebaseSessionGate.kt:17,43-52).
- Logout/wipe apaga arquivo + a própria chave do Keystore (SecureSessionStore.kt:45-49; SessionManager.kt:98-113).
- Identidade Firebase validada: UID do Firebase precisa bater com o UID da sessão, senão bloqueio total (UidMismatch) e signOut (FirebaseSessionGate.kt:51-52; SessionManager.kt:80-89).

Ausência de logs de credenciais
- AuthApiClient nunca loga Authorization/senha/token/corpo; o catch genérico reduz a exceção a categoria de transporte, sem logar URL+token (AuthApiClient.kt:20-23,90-92).
- AuthRepo.postJson não loga corpo; classifyError devolve apenas categoria (TIMEOUT/SSL/NETWORK/…) (AuthRepo.kt:44-50,73-74).
- Varredura por Log de password/session-token/Bearer/customToken/firebaseToken: nenhum resultado. O ÚNICO log contendo "token" é o registration token do FCM TRUNCADO a 12 caracteres (Fcm.kt:48: `token=${token.take(12)}…`), além de logs de deviceId/uid para diagnóstico (Fcm.kt:34,48-55). Ser preciso: isso é token de dispositivo do FCM (não senha, não token de sessão, não Bearer); ainda assim é identificador — truncado. Nenhuma credencial de usuário é logada.

Ausência de dados fictícios
- Nenhum usuário/tarefa/evento/mensagem hardcoded: todos os dados vêm em tempo real do Firestore (TaskRepo.kt:118-136; EventRepo.kt:36-54; ChatRepo.kt:40-64; UsersRepo.kt:13-56).
- Login não usa credenciais embutidas; a senha existe só nos parâmetros locais da chamada e é descartada após a tentativa (ServerAuthRepository.kt:18-19; SessionManager.kt:63,73-76).
- Fixtures/mocks existem apenas em testImplementation/debugImplementation (Roborazzi/Robolectric/org.json de teste) e NÃO vão no APK (build.gradle:195-207). Login client-side legado (users.get + Crypto.verify) foi REMOVIDO (Crypto.kt:32-36; AuthRepo.kt:80-84).
