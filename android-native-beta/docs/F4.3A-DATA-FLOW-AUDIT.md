## 0. Fatos transversais (valem para todas as linhas)

- **Criptografia em trânsito = SIM (TLS/HTTPS) para 100% do tráfego, fail-closed comprovado:**
  - Manifest: `android:usesCleartextTraffic="false"` + `networkSecurityConfig` — `AndroidManifest.xml:20-21`.
  - `res/xml/network_security_config.xml`: `<base-config cleartextTrafficPermitted="false" />`.
  - `AuthApiClient.post()` rejeita qualquer URL não-`https://` ANTES de conectar — `AuthApiClient.kt:66-68`.
  - Firestore/Firebase Auth/FCM: SDK Google usa TLS por padrão (deps em `app/build.gradle`, firebase-bom 33.7.0).
- **Nenhum SDK de analytics/telemetria/publicidade.** `build.gradle` inclui SOMENTE `firebase-auth`, `firebase-firestore`, `firebase-messaging`, `firebase-functions`. NÃO há Firebase Analytics, Crashlytics nem Advertising ID. Grep por `Analytics|Crashlytics|advertising|Adid` = zero ocorrências de coleta. Logs são apenas `android.util.Log` locais (logcat no aparelho), não transmitidos.
- **Sem coleta de localização do dispositivo.** Não há permissão de localização no Manifest. O campo `location` de eventos (`EventRepo.kt:22`) é texto digitado pelo usuário (nome do local), não GPS.
- **Destinos externos (todos = infraestrutura Google):**
  - **Cloud Run / Cloud Functions Gen2** (backend oficial): `loginUser`, `getUserSelf`, `changePassword`, `issueFirebaseAuthToken`, `registerFcmToken`, reset de senha. URLs em `build.gradle` (`AUTH_*_URL`, `PASSWORD_RESET_*_URL`).
  - **Firebase Firestore** (coleções `tasks`, `events`, `chats/messages`, `users`).
  - **Firebase Auth** (sign-in com custom token).
  - **FCM** (provisionamento de token de push + entrega de mensagens).
  - **Coil** carrega URLs de foto/avatar (`build.gradle`: `coil-compose:2.7.0`; uso em `UsersRepo.kt:21` campo `photo`) — busca de imagem em host externo, sempre HTTPS.
- **NOTA DE DATA SAFETY — "compartilhado":** por mandato do owner, tratar Firebase/Google Cloud (Auth/Firestore/FCM) como **compartilhamento com Google**. Ressalva factual: pela definição literal do Play, dados processados por um "service provider" (Google/Firebase) podem ser declarados como *coletados/processados* sem serem *"shared"*. A classificação final "Data shared" vs "Data collected" é decisão do owner/jurídico → **[OWNER: decidir classificação Play "shared" vs "collected" para dados processados por Firebase]**.
- **Exclusão pelo usuário:** NÃO há função in-app de "excluir minha conta/meus dados". Logout apaga só o local (ver linha 8). Dados server-side (users/tasks/events/chats) são geridos por admin (status `removido/excluido/inativo` em `ServerAuthRepository.kt:41`). Canal de exclusão a definir → **[OWNER: preencher e-mail/procedimento de solicitação de exclusão de dados]**.

- **Obrigatório/opcional:** Obrigatório para usar o app.
- **Exclusão:** Não self-service → [OWNER].

## 2. Senha de login

## 3. Cadastro (auto-registro): nome, cargo (role), telefone, e-mail, senha
- **Categoria Play:** Personal info > Name; Email address; Phone number; (senha = credencial).

- **Transmitido:** SIM → **escrita DIRETA no Firestore `users`** com `{name, role, phone, email, pass, salt, status:"pendente", admin:false, createdAt}`. A senha é hash `"s2:"+sha256(salt+"|"+senha)` (não texto puro), mas o hash+salt trafegam e ficam no Firestore.
- **Evidência:** `AuthRepo.kt:86-107`; hash em `Crypto.kt:22-30`.
- **Finalidade:** Account management (criação de conta; aprovação por admin).
- **Em trânsito:** HTTPS/TLS (SDK Firestore).
- **Obrigatório/opcional:** Opcional (contas também podem ser criadas por admin; este é um caminho alternativo).
- **Exclusão:** Não self-service → [OWNER].

## 7. Token de sessão server-side (Bearer)
- **Categoria Play:** normalmente NÃO declarado (credencial de sessão interna, não é dado do usuário exposto). Registrar como dado de segurança interno.
- **Coletado/gerado:** SIM (retornado por `loginUser`).
- **Transmitido:** SIM, mas **apenas** como header `Authorization: Bearer` para os endpoints Cloud Run (`getUserSelf`, `changePassword`, `issueFirebaseAuthToken`, `registerFcmToken`). NUNCA enviado ao Firestore, log, Intent, deep link, notificação, clipboard.
- **Em repouso:** SOMENTE criptografado (AES-256-GCM, Android Keystore, não-exportável, atado ao aparelho).
- **Evidência:** `AuthApiClient.kt:78`; `SecureSessionStore.kt:22-38`; `SessionCipher.kt`/`KeystoreSessionCipher` `SessionCipher.kt:39-104`; `SecureSession.kt:10-16` (comentário "NUNCA em claro"); `AuthContract.kt:8-12`.
- **Em trânsito:** HTTPS/TLS.
- **Exclusão:** `logout()`/`wipe()` apaga arquivo + chave do Keystore — `SessionManager.kt:99-113`; `SecureSessionStore.kt:44-49`.

## 10. Firebase ID Token (gerido pelo SDK)

- **Destino:** Google.

## 11. FCM registration token (token de push do dispositivo)
- **Categoria Play:** Device or other IDs.
- **Coletado:** SIM — obtido de `FirebaseMessaging.getInstance().token` (provisionado pela Google/FCM).
- **Transmitido:** SIM → Cloud Run `registerFcmToken` com `{token, deviceId, platform}` + Bearer. Também gravado em SharedPreferences `"fcm"` (chave `token`) em **texto claro** (não cifrado). O token antigo também é legível na coleção `users.fcmTokens` (leitura de equipe, ver linha 17).
- **Evidência:** `AuthApiClient.kt:56-62`; `Fcm.kt:31-52` (get + register + prefs); `AppFirebaseMessagingService.kt:17-31` (onNewToken); `ServerAuthRepository.kt:141-157`.
- **Finalidade:** App functionality (entrega de notificações push).
- **Em trânsito:** HTTPS/TLS.
- **Obrigatório/opcional:** Efetivo quando logado e com notificações ativas (permissão `POST_NOTIFICATIONS` é opcional em runtime — `AndroidManifest.xml:5`).
- **Exclusão:** Rotaciona/aposenta por `deviceId` no backend; sem remoção self-service in-app → [OWNER].
