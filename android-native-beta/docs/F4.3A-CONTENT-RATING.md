**Interação/UGC dentro do público-alvo:**

Mitigadores reais a citar na revisão: (i) acesso restrito a membros da equipe aprovados por admin (`status:"pendente"`), (ii) controle de acesso via Firestore Rules server-side, (iii) gestão de usuários por admin (status `removido/excluido/inativo`). **[OWNER: confirmar]** se será necessário adicionar denúncia/bloqueio in-app ou se o enquadramento "ferramenta corporativa interna de equipe fechada" é suficiente para a revisão; documentar a política de conteúdo do usuário.

## (c) PAÍSES / REGIÕES — RECOMENDAÇÃO

**Recomendação: publicar inicialmente apenas no BRASIL.** **[OWNER: confirmar lista de países]**

Racional:
1. **Idioma e público reais:** app 100% pt-BR, ferramenta interna de uma organização brasileira (identidade `idseven`); os usuários efetivos são a equipe no Brasil.
2. **Superfície jurídica mínima:** restringir ao Brasil mantém a exposição regulatória sob **LGPD** apenas, evitando obrigações adicionais de GDPR (UE/Reino Unido), CCPA/CPRA (Califórnia) etc. enquanto a política de privacidade e os fluxos de exclusão ainda dependem de itens [OWNER] pendentes.
3. **Consistência de infraestrutura:** backend Cloud Run/Cloud Functions em `us-central1` funciona globalmente, mas não há necessidade operacional de distribuição ampla para um app de equipe fechada.
4. **Expansão incremental:** é trivial adicionar países depois; começar restrito reduz risco de revisão e de suporte antes de validar a v1.

Considerações adicionais **[OWNER: confirmar]**:
- Por ser ferramenta corporativa de equipe fechada, avaliar se a **produção pública aberta** é realmente desejada ou se convém uma **faixa de teste fechada/interna** (closed/internal testing) ou distribuição gerenciada.
