## 3. Racional de impacto ZERO — quatro invariantes que fecham cada componente

Toda a matriz se reduz a quatro invariantes. Um `.md` em `android-native-beta/docs/` num branch dedicado satisfaz os quatro para **todos** os componentes do §2:

- **(I1) Sem código compartilhado alterado.** Os componentes congelados residem em `desktop/`, `cloudflare-worker.js`, `functions/`, rules e backend Cloud Run — árvores disjuntas de `android-native-beta/docs/`. Nenhum build ou runtime importa `docs/`. Um doc não é referenciado por nenhum grafo de compilação nem por nenhum artefato de execução ⇒ nenhum byte de Desktop/Worker/Functions/Rules/PWA muda.
- **(I2) Sem deploy.** Todos os pipelines que tocam produção (`deploy-worker.yml`, `firestore-rules-deploy.yml`, `firebase-functions-deploy.yml`, releases Desktop) são **`workflow_dispatch`** (vários com guard `confirm_deploy`). Nenhum observa `push` de docs. F4.3A não invoca nenhum deles. Além disso, **não há Play publishing automatizado no repo** (sem `fastlane/`, sem service-account de Play): a publicação na Play é ação manual do owner no Console.
- **(I3) Sem recompilar o AAB.** O AAB oficial é um artefato **pinado** (run `30205814202`); `build-android-official.yml` é o único que o produz e está **preso ao branch `android/f42e-official-identity-signed-build`** (trigger `push` filtra `branches: [android/f42e-official-identity-signed-build]`, `paths: ['android-native-beta/**']`). Como builds assinados não são bit-a-bit reprodutíveis, qualquer rebuild geraria SHA-256 diferente do pinado — por isso F4.3A **não** vive em f42e (ver §4). Fora de f42e, nenhum trigger de build casa ⇒ AAB/APK mantêm `1c14d39…` / `dca77db…` intactos.
- **(I4) Sem endpoint/segredo/dado tocado.** Docs não contêm rotas, URLs, tokens nem chaves executáveis. O app continua falando com o mesmo Cloud Run / Firestore / FCM porque o binário (o AAB) é o mesmo. Dado real de produção só é lido/escrito pelo app em execução; texto inerte não muta Firestore/Auth. Nenhum usuário/tarefa/screenshot fictício é fabricado.

Portanto, para **cada** item do §2, o impacto é ZERO pela conjunção I1∧I2∧I3∧I4: sem código compartilhado alterado (I1), sem deploy (I2), sem recompilar o AAB (I3), sem endpoints/segredos/dados tocados (I4).

## 4. Efeito colateral observado + mitigação (exigência de branch)

**Efeito colateral (confirmado no repo).** Em `main` existe `.github/workflows/build-android-native-beta-manual.yml`, com trigger:

```
on:
  workflow_dispatch:
  push:
    branches: [main]
```

Qualquer `push` a `main` dispara esse workflow. Ele faz `checkout` do ref `feat/android-native-saas` (código legado, `versionName 1.0.14`), roda `gradlew clean assembleRelease` (working-directory `android-native-beta`) com **debug keystore** (assinatura de teste) e restaura `GOOGLE_SERVICES_JSON_BETA`; a saída é **apenas um artefato APK** (`idseven-nativebeta-1.0.14-beta-notify-debug-fix-<sha>`). Ele é `permissions: contents: read`, **não gera AAB/`bundleRelease`, não assina com a chave oficial, não publica na Play e não faz deploy** — o próprio cabeçalho declara "TEMPORÁRIO… REMOVER após validar. Não toca PWA, Worker, Firebase web, secrets nem código do app — só CI." Ou seja: é um build descartável de código legado que **não toca o AAB oficial** (129/1.0.0), o qual é produzido só por `build-android-official.yml` no branch f42e.

(Nota de precisão terminológica: o workflow constrói o estado **legado do módulo beta** em `feat/android-native-saas @ 1.0.14`, não o diretório top-level `android-native` — que no working tree está em `0.2.15`, versionCode 17. A substância bate: código legado, APK debug descartável, sem publish/deploy, AAB oficial intocado.)

**Mitigação (dupla, exigida por F4.3A).** F4.3A deve viver num **branch Android dedicado** (ex.: `android/f43a-play-release-readiness`) que **não seja `main` nem `f42e`**:
- **Não `main`** ⇒ não casa `build-android-native-beta-manual.yml` (evita até o build descartável legado).
- **Não `f42e`** ⇒ não casa `build-android-official.yml` (cujo `paths: ['android-native-beta/**']` **incluiria** `android-native-beta/docs/**`); assim o AAB oficial não é recompilado (protege I3).
- Um branch novo `android/f43a-*` **não casa nenhum** trigger de `push`: `build-android-native-beta.yml` filtra `feat/android-native-saas` e `android/f42c-…`; `build-android-native.yml` filtra `feat/android-native-kotlin`. Resultado: **zero CI, zero build, AAB/APK oficiais com SHA-256 idênticos**.

**Resumo.** F4.3A = somente Markdown em `android-native-beta/docs/`, em branch Android dedicado ≠ `main` ≠ `f42e`.
