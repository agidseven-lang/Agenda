## PARTE 0 — VISÃO GERAL (as 3 perguntas iniciais do assistente)

**Pergunta 1 — "Does your app collect or share any of the required user data types?"**
**Resposta: SIM (Yes).** O app coleta e transmite dados do usuário (e-mail, nome, telefone, foto de perfil, conteúdo de tarefas/eventos, mensagens de chat, identificadores de dispositivo) para infraestrutura Google (Cloud Run / Firestore / Firebase Auth / FCM).

**Pergunta 2 — "Is all of the user data collected by your app encrypted in transit?"**
**Resposta: SIM (Yes).** 100% do tráfego é HTTPS/TLS, fail-closed:
- `usesCleartextTraffic="false"` + `networkSecurityConfig` (`AndroidManifest.xml:20-21`; `network_security_config.xml`).
- Cliente de auth rejeita URL não-`https://` antes de conectar (`AuthApiClient.kt:66-68`).
- SDKs Firestore/Auth/FCM usam TLS por padrão.

**Pergunta 3 — "Do you provide a way for users to request that their data be deleted?"**
**Resposta: SIM (Yes), via canal externo — NÃO há exclusão self-service in-app.** O logout apaga apenas os dados locais (arquivo de sessão cifrado + chave do Keystore — `SessionManager.kt:99-113`). Dados server-side (users/tasks/events/chats) são geridos por admin (status `removido/excluido/inativo` em `ServerAuthRepository.kt:41`).
- Deve-se informar na Play uma **URL de solicitação de exclusão** (obrigatória pela política de exclusão de contas do Google, já que o app permite auto-registro).
- **[OWNER: confirmar]** URL da página de solicitação de exclusão de conta/dados e/ou e-mail de suporte + procedimento.

**Público-alvo / Play Families Policy:** app de agenda corporativa para equipes de trabalho — **NÃO** é direcionado a crianças. "Committed to Google Play Families Policy" = **Não** (público adulto/força de trabalho). **[OWNER: confirmar]** faixa de público-alvo no Content/Target audience.

## PARTE 1 — DATA COLLECTION & DATA SHARING (por tipo de dado da Play)

> **Convenção de "compartilhamento" (nota crítica e verdadeira):** por mandato do owner, os dados processados por Firebase/Google Cloud (Auth/Firestore/FCM/Cloud Run) são tratados como **compartilhados com o Google**. Ressalva factual: pela definição literal da Play, transferência a um **"service provider"** (Firebase processa em nome do desenvolvedor) pode ser declarada como **coletada** sem ser **"shared"**. A escolha final "Shared" vs. apenas "Collected" para dados que ficam dentro do Firebase é **[OWNER: confirmar]**. Abaixo cada linha traz as duas leituras; escolher uma antes de publicar.
>
> **"Processed ephemerally" (efêmero):** em Data Safety significa manter só em memória, sem enviar para fora nem persistir. Todos os itens abaixo marcados "Coletado" são **enviados a servidor e/ou persistidos** → **Não efêmero**, salvo indicação.
> **"Encryption in transit"** = **SIM** em 100% das linhas.

### 5. Personal info — Password / credencial
- **Situação na Play:** **A Play NÃO possui um tipo de dado dedicado a "senha/credencial".** As opções de "Personal info" são Name, Email, User IDs, Address, Phone, Race/ethnicity, Political/religious, Sexual orientation, **Other info**. Portanto a senha **não é declarável como tipo próprio**; se o owner optar por declará-la, o encaixe é **Personal info > Other info**.
- **Fato do app:** senha digitada é enviada a Cloud Run `loginUser`/`changePassword`/reset sobre TLS (nunca persistida no aparelho — `SessionManager.kt:63`); no auto-cadastro grava-se **apenas hash+salt** `"s2:"+sha256(salt|senha)` em Firestore, não texto puro (`Crypto.kt:22-30`).
- **Recomendação:** conforme prática comum e orientação do Google, credenciais de autenticação normalmente **não são declaradas** como tipo de dado; caso o jurídico prefira transparência total, declarar em **Other info** (Collected, Account management, obrigatório, TLS, não efêmero).
- **Decisão:** **[OWNER: confirmar]** declarar ou não sob "Other info".
