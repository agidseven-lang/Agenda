# F4.3C4C — Prova comparativa: protótipo × modelo da Desktop 1.0.185 (PROIBIDO)

> **Objetivo deste relatório**: provar, ponto a ponto e com testes executáveis, que o
> protótipo F4.3C4C **NÃO reintroduz** o modelo de autenticação silenciosa da Desktop
> 1.0.185 (F4.2F), que causou incidente em produção e foi integralmente revertido
> (1.0.186 = roll-forward byte-equivalente da 1.0.184, sem a ponte silenciosa).

## 1. O que foi o modelo 1.0.185 (F4.2F) — e por que é PROIBIDO

A Desktop 1.0.185 introduziu uma "ponte" de Firebase Auth **silenciosa**:

1. Iniciava autenticação **automaticamente no arranque** do app, sem ação explícita
   do usuário e sem estado visível/auditável;
2. Operava **acoplada ao fluxo existente** (startup) em vez de isolada atrás de uma
   chamada explícita — qualquer efeito colateral aparecia em superfícies não
   relacionadas (produção);
3. Tinha modos **fail-open** por flag: falha de autenticação não bloqueava o acesso —
   o app seguia operando como antes (anônimo);
4. O resultado foi um incidente em produção (regressão na superfície Card
   Premium/links de cliente) e o **rollback completo** da versão.

Por isso a AUTORIZAÇÃO F4.3C4C fixa: **"PROIBIÇÃO DE AUTENTICAÇÃO SILENCIOSA — NÃO
REINTRODUZIR O MODELO DA DESKTOP 1.0.185"**.

## 2. Comparação estrutural (modelo 1.0.185 × protótipo F4.3C4C)

| Dimensão | Desktop 1.0.185 (F4.2F) — PROIBIDO | Protótipo F4.3C4C (este) | Prova (teste) |
|---|---|---|---|
| Quando a autenticação inicia | Automaticamente no arranque (silenciosa) | **Somente** quando `ensureAuthenticated()` é chamado explicitamente após login | A12 |
| Side effects no construtor | Sim (bridge armada no boot) | **Nenhum** — construtor apenas grava dependências; estado `Idle` | A12 |
| Visibilidade do estado | Invisível ao usuário/dev | 11 estados explícitos e auditáveis (`AuthState`) | A2, A4–A10, S30 |
| Falha de autenticação | Fail-open (app seguia anônimo) | **Fail-closed**: qualquer falha => estado de bloqueio; Firestore continua NEGADO | A9, F22, S30 |
| Fallback anônimo | Existia na prática (app operava sem auth) | **Inexistente**: nenhum `signInAnonymously`, nenhum fallback | A1, F14, SEC39 |
| Offline / backend fora | Seguia operando aberto | `Offline` + Firestore NEGADO (não abre acesso) | S30 |
| Identidade | uid não confrontado com a sessão local | `currentUid == session.uid` obrigatório; divergência => `UidMismatch` + `signOut` | A10 |
| Escalada via corpo da requisição | n/a (sem endpoint dedicado) | uid/role/admin do body **IGNORADOS**; uid deriva da sessão Bearer | A11 |
| Sessão expirada/revogada/inativo | Não bloqueava | 401 => `SessionExpired`; 403 => `SessionRevoked` (inclui inativo); bloqueio total | A5–A7, S27, S29 |
| Listeners no logout/troca | Sem gestão central | Todos rastreados e **encerrados** no logout/dispose; não sobrevivem à troca | F20, F21, S25, S26 |
| Rules pressupostas | Rules abertas de produção | Rules-alvo F4.3C3 **deny-by-default**, byte-idênticas (SHA-256 pinado) | SEC38, F14–F18 |
| Ambiente | Produção (stable/latest) | **Somente emuladores** + backend sintético + project fictício | SEC34–SEC37 |

## 3. Resultado executável

Suíte completa (40 testes) executada com Auth Emulator + Firestore Emulator +
backend sintético, project fictício `demo-agenda-id-seven-f43c4c`:

```
F4.3C4C PROTÓTIPO (emuladores): 40 OK, 0 FALHOU (de 40)
```

Os testes que materializam a prova anti-1.0.185:

- **A12** — instância criada e 120 ms de espera: estado permanece `Idle`, backend
  **não** é chamado, Firebase **não** autentica sozinho (nenhuma auth no arranque);
- **A1 / F14 / SEC39** — sem login, toda leitura (usersPublic, tasks, events) recebe
  `permission-denied` (a "Desktop anônima" simulada continua bloqueada pelas
  Rules-alvo — nada abre por padrão);
- **A9 / F22** — falha na autenticação Firebase NÃO libera Firestore (sem fail-open);
- **S30** — backend inalcançável => `Offline` e Firestore continua NEGADO;
- **A10** — identidade divergente => `UidMismatch` + `signOut` imediato;
- **F20 / F21 / S25 / S26** — logout/troca de usuário encerra listeners e limpa estado.

## 4. Conclusão

O protótipo implementa **autenticação explícita, visível, fail-closed e derivada da
sessão** — o oposto estrutural do modelo 1.0.185 em todas as dimensões acima, com
cada dimensão coberta por teste executável. A Desktop oficial 1.0.191 (Golden
Master) permanece intocada; este protótipo é somente o CONTRATO de uma futura
Desktop, validado contra as Rules-alvo F4.3C3 em emulador.
